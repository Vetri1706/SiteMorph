# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.

## SiteMorph product direction

- Freeze frontend visual polish at the current demo-quality state unless the user explicitly reopens UI work; prioritize the live Forma/FortyGuard backbone.
- Use partnership-oriented Autodesk copy: “FortyGuard adds historical thermal context to Forma.”
- When mock mode is enabled, completed analysis must be labeled “Demo analysis loaded”; never imply mock data is a live site result.
- Treat Climate DNA as the primary product and visual differentiator. Give it the highest fidelity and deepest working interaction.
- Keep the Site tab as lightweight entry plumbing around Forma connection, site-limit selection, and Analyze Site.
- Treat Compare as a bonus workflow backed by precomputed candidates; do not imply live design generation or live Forma re-analysis where it is mocked.
- The critical integration seam is Forma site geometry -> SiteMorph backend/FortyGuard -> normalized Climate DNA -> Forma canvas overlay.
- Never add an independent 3D viewer inside the extension panel.
- Inside Forma, SiteMorph must start with no selected Site Limit, site geometry, or Climate DNA. A Site Limit becomes the AOI only from a real Forma canvas selection received after the user enters selection mode.
- Keep the real Forma element path for the selected Site Limit and use Forma element-color highlighting for selection feedback; never target mock `overlay/...` paths in embedded mode.
- Climate overlays must clip to and visually cover the complete selected Forma Site Limit. Where sparse 60 m FortyGuard cells leave parcel-edge gaps, extend the nearest real tile value to the boundary; never invent additional spatial variation.
- Do not assume a warehouse program in live Forma mode. The warehouse brief and candidates are demo-only precomputed content and must remain gated to mock mode.
- Rank live build zones only from real FortyGuard tiles sampled across representative dates using 40% lower mean temperature, 35% lower persistence, and 25% lower exceedance. Include `time_of_measure` for peak hour evidence.
- If the sampled tiles do not show meaningful within-site separation, keep every tile Moderate and explicitly report no reliable separation; never invent a preferred compass direction.
- Keep Design disconnected until a real Climate Design Brief exists. When it does, expose one live Generate Building action before adding multiple candidates or Compare.
- Use hot-season multi-year evidence for live thermal exposure and do not dilute Phoenix design conditions with mixed winter/spring averages. While prototype credits are non-renewable, Credit Saver mode defaults to one representative July date from 2023, 2024, and 2025; the broader Jun–Sep set is an explicit full-evidence run only after approval.
- Label exceedance and persistence aggregation explicitly: mean exceedance, mean persistence, and maximum continuous persistence are different statistics and must never be presented as directly comparable totals.
- When FortyGuard remains spatially uniform, say: “The parcel is thermally uniform at FortyGuard resolution. Use site-wide heat constraints and let Forma optimize internal building placement.”
- Render live thermal tiles through `Forma.terrain.groundTexture` for the 2D canvas. Match native Forma analysis behavior by leaving buildings in their normal model appearance so they occlude the ground raster; do not paint every building with the ground bucket and do not rely on a flat generic mesh as the primary overlay.
- Position SiteMorph as a climate-to-design and site-feasibility agent: FortyGuard supplies historical and site evidence, Forma supplies native design-performance analysis, and SiteMorph translates both into constraints, geometry, and an auditable report.
- When FortyGuard cannot reliably separate a parcel at its native resolution, do not recommend a directional build zone. Show low thermal-zoning confidence and a site-wide Climate Design Brief instead.
- In the live workflow, create actual Forma geometry, run a native Forma analysis, and make at most one explainable revision before expanding to multiple options or Compare.
- Street-view evidence belongs at parcel edges or access points and must degrade explicitly to unavailable when FortyGuard has no imagery.
- Treat building-use recommendations as preliminary until zoning, land use, access engineering, utilities, and market evidence are connected; make those limitations visible in the report.
- Climate DNA is now considered sufficiently strong for the prototype; prioritize the live design loop and its visible outcomes.
- A completed Forma analysis must always resolve the SiteMorph workflow. Use the Site Limit as the native Sun analysis area so the embedded SDK can return a ground grid, and degrade explicitly to native-result-only status if the grid is unavailable.
- Generated buildings must avoid readable existing-building footprints, validate conflicting area inputs, test one revision, and retain the better measured result instead of blindly accepting the revision.
- Revit is the next handoff target. Use Forma’s native proposal-to-Revit add-in workflow for the actual transfer, and never label SiteMorph’s JSON or OBJ as direct cloud sync or native BIM.
- Title the exported deliverable “SiteMorph — Site Intelligence & Climate Design Report”; avoid “feasibility” unless zoning, legal, financial, and entitlement evidence is actually connected.
- Present site-facing timestamps in the site's local time and retain UTC only as secondary evidence.
- Never render unavailable report evidence as dash-filled metrics. Omit missing fields and state once that the evidence was unavailable for the analysis window.
- After a building is generated, the report must embed the captured Forma proposal, its parameters, validation IDs/results, the SiteMorph revision decision, a final recommendation, and an evidence trail.
- Keep the South Phoenix Site Limit at 359,376 ft² / 8.25 acres. The earlier 5+ acre guidance was a demo-AOI choice for spatial context, not a universal Forma requirement and not a building-area requirement.
- For the live warehouse example, interpret 85,000 ft² gross area with a 78,000 ft² footprint and one main floor as a deliberate 7,000 ft² office/mezzanine component; never silently reduce the gross area to the footprint.
- The current OBJ is generic concept geometry, not native walls, roofs, floors, or openings. Keep it only as an optional reference export; do not present it as the Revit handoff.
- Make the dimensioned 2D program/site plan the primary SiteMorph design artifact. Keep the live Forma mass for native analysis and native Forma-to-Revit transfer. Export SiteMorph JSON only as optional design evidence for audit or future automation.
- Live program plans must be typology-aware. Logistics may show docks, warehouse and truck court, but healthcare, office, education, residential, hotel, retail, mixed-use and unknown building types must receive appropriately labelled preliminary program zones and circulation/arrival edges; never force a warehouse diagram onto a non-warehouse brief.
- Generate a separate typology-aware terrain concept overlay from the live requirements and approved mass, showing parking, preferred access, sheltered arrival/loading/service edges, operational outdoor space and unallocated landscape. Keep it visibly preliminary and constraint-based; never describe it as code-compliant optimization. The native Forma floor stack remains the analysis and Revit-transfer geometry.
- Before manual Project requirements, offer a no-paid-API Site Fit Advisor that deterministically ranks typology-specific briefs from the selected Forma Site Limit, Climate DNA, parcel compactness, parking allowance and operational-space assumptions. Let the user apply any suggestion or enter a fully manual brief. Always expose missing zoning, access, utilities, market, entitlement, fire and parking-code evidence; never call the result legal, financial or highest-and-best-use advice.
- Revit does not natively import SiteMorph JSON. Treat the persisted Forma proposal as the actual Revit handoff and guide the user through Proposals → Revit → Send to Revit add-in (Beta). SiteMorph may prepare, validate and highlight its proposal geometry, but must not claim it can programmatically invoke that host menu while the public embedded-view SDK exposes no Revit-send trigger. Keep JSON as an optional SiteMorph evidence/audit export, not the BIM import.
- Generated Forma masses must use the real terrain elevation sampled beneath their placed footprint in the proposal transform; never leave the building at project-local `Z = 0`, because the Forma-to-Revit add-in preserves that vertical offset.
- FortyGuard credits are non-renewable for this prototype. Persist completed analysis responses by canonical AOI plus dates, threshold, resolution, timezone, and cache schema. Reopening Forma, restarting the server, retrying, or changing unrelated UI/design code must reuse the saved result without another FortyGuard request.
- Keep FortyGuard fallback keys server-side only and preserve their configured order. Move from the primary to a fallback only after an explicit invalid/revoked credential or exhausted-credit response; never rotate after an ambiguous network failure, and never let additional keys expand the public lifetime activity budget.
- Persist each submitted FortyGuard activity ID immediately and resume its status polling after interruption. The public hosted run must never exceed 12 core thermal activities. For the local Forma extension, the user has explicitly approved a complete first run of at most 15 activities: 12 core thermal plus environmental parameters, satellite segmentation and street-edge context. After the canonical aggregate is saved, every reopen and retry must be cache-only and create zero new activities.
- Treat a completed FortyGuard `map_data` FeatureCollection with zero features as terminal `NO_THERMAL_COVERAGE`: persist the saved activity IDs as unavailable, mark dependent metrics skipped, never fabricate Climate DNA, and never resubmit those activities. Accept valid Polygon tiles and normalize valid MultiPolygon tiles without discarding provider evidence.
- FortyGuard Safe mode is the default while credits are low: `FORTYGUARD_MAX_NEW_ACTIVITIES=0` and the live UI requests cache-only analysis. Raising the limit or enabling paid analysis requires explicit user approval immediately before the run.
- Use the compact four-tile blue mark from the user's supplied reference as SiteMorph's canonical logo: large `#2E9EFF` top-left and `#68C4FF` bottom-right tiles, smaller `#0C79D8` top-right and bottom-left tiles, on `#181818`. Keep the same vector geometry in the 4K master, Forma extension metadata, browser/app icons, panel header, and report; do not return to the `SM` placeholder or the earlier parcel mark.
- Keep that four-tile mark prominent and memorable in the product lockup, not reduced to a tiny utility icon. Use the tightly cropped vector mark at about 48 px in a roughly 92 px header row, paired with a clearly readable SiteMorph wordmark and tagline.
- Public README and demo GIFs must be captured from the real Forma workflow at native browser resolution, use product-focused crops that keep SiteMorph panel text legible, and use a stable no-dither palette; never upscale low-resolution footage or ship visibly speckled GIF encoding.
- Add a first-class residential subdivision mode that deterministically generates auditable lot, road, open-space, canopy and separate-dwelling concepts from explicit user assumptions. Preview multiple local options, but write only the selected option as native Forma floor-stack geometry and validate the complete proposal once with native Forma analysis.
- Make FortyGuard historical evidence structurally central to subdivision ranking: combine real hot-season temperature (35%), mean persistence (25%), maximum continuous persistence (20%) and mean exceedance (20%) through an exposed weighted geometric mean, then multiply by exposed plan-mitigation factors. Retain the actual peak thermal hour as supporting evidence and evidence-completeness context only; peak-time availability must never increase or decrease numerical heat burden. Optional surface/canopy evidence may contribute only when actually available; never invent parcel-scale directional variation when FortyGuard is uniform.
- Treat generated trees and landscape points as preliminary SiteMorph mitigation assumptions, not surveyed vegetation, species selection, code-compliant planting or validated native BIM. Keep lots, roads and open-space graphics clearly labelled as concept overlays until persistent geometry is separately verified.
- When a subdivision is built, persist its conceptual roads, pedestrian paths, lot/open-space terrain shapes and recognizable species-neutral low-poly 3D trees as one refresh-safe, virtual SiteMorph-authored Forma context root. Use `groundTexture` only for pre-build previews and transient labels. Keep the separate dwelling floor stacks as the native Forma-to-Revit source and never claim that the context root is surveyed civil geometry, planting design or Revit BIM.
- Persistent subdivision tree assets must be serialized with glTF's Y-up coordinate convention so Forma displays them upright. Verify the persisted world mesh meets sampled terrain and has the expected vertical height and horizontal canopy span; reject sideways, underground, floating, or degenerate trees instead of accepting only their instance transform.
- Use clear, comfortably sized enterprise typography inspired by the Zoneomics reference. The panel's visual character should use a deep-navy geospatial header, blue/teal accents, and restrained spatial-network imagery inspired by ArcGIS without copying its branding.
- FortyGuard credit reporting must prefer a dated persisted last-known balance when the live usage endpoint is unreachable. In Safe mode, say "Not checked" when no snapshot exists; never label the balance simply "Unavailable".
- Export reports as genuine DOCX packages with deterministic Word pagination, fixed-width tables, and inline imagery; never disguise HTML as a `.doc` file.
- Label FortyGuard-only climate layers as coarse historical baselines. Reusing the same real 60 m cells across metrics should keep the same spatial footprint; only native Forma result grids may add finer design-scale variation.
- The exported SiteMorph report must carry the same deep-navy geospatial masthead and teal accent system as the extension panel, and must embed available imagery rather than linking to runtime-relative image paths.
- Keep the README architecture as a source-backed 4K diagram with an editable vector source. It must show the real Forma, SiteMorph and FortyGuard boundaries, exact live routes, cache/credit/fail-closed behavior, native design and Revit handoff paths, plus implemented functional and non-functional requirements; never replace it with an aspirational or text-inaccurate generated flowchart.
- When a selected Forma Site Limit matches a persisted cache in Safe mode, restore its Climate DNA automatically. After restoration, the primary Site action opens Climate DNA instead of asking the user to resume again.
- When the Forma selection changes to another valid Site Limit—even in a different project—re-read and commit that Site Limit's actual geometry and current project context before cache lookup. Selecting a building, tree, or overlay must never replace the active Site Limit path or pair it with stale AOI geometry.
- For the South Phoenix demo parcel, the dated archived satellite, surface-segmentation, street-source, and street-segmentation images may be reused as clearly labeled supporting context without a new FortyGuard request; do not describe them as current-run evidence.
- After the live design loop, combine FortyGuard's spatially coarse historical heat burden with readable native Forma Sun and Rapid Wind grids in a separately labeled `Forma-resolved Climate Response`. Keep the prototype weights and coverage visible, renormalize only across available real inputs, and degrade to `partial` when a grid is unavailable; never create apparent resolution with smoothing, random noise, or fabricated sub-cells.
- The public no-login Sites deployment may use a server-side FortyGuard key only behind a persistent lifetime ceiling of 12 new activities. It must check saved Climate DNA first, require an explicit in-panel confirmation before the one uncached thermal run, keep optional enrichment disabled, persist submission state and results, and fail closed after the hosted allowance is reserved.
- Pause further ChatGPT Sites releases while its hosted FortyGuard workflow remains unreliable. Use the local Forma extension for active development and demonstrations, and treat Vercel—connected from the `Vetri1706/SiteMorph` GitHub repository—as the intended final public deployment target when the user explicitly resumes deployment work.
- Keep SiteMorph independent of Archistar and other third-party geometry generators. Use only generic planning concepts visible in public workflows as clean-room research; never copy proprietary templates, defaults, UI, assets, branding, or generation logic. Separate development use (such as logistics, residential, office, healthcare, education, hotel or retail) from physical form generators. Build SiteMorph-authored deterministic native-Forma form adapters for subdivision, terrace housing, townhouses, garden apartments, apartments, commercial podium/tower or slab forms, mixed use, hotel, carpark, duplex, manor-house-style small multi-unit housing, and boarding housing, then combine compatible use and form models. Every design input must carry provenance, and zoning/code variables such as setbacks, privacy spacing, dwelling density, deep soil, open-space mandates, parking ratios and fire access must remain visibly unconfirmed unless evidence or a user-confirmed rule supplies them.
